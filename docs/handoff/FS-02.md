## 2. Detailed Findings & Verification Evidence

### F48 — Hardcoded and Incomplete Frontend Integration
- **Changes**:
  - `frontend/src/api.js`: Made `API_BASE_URL` configurable via `import.meta.env.VITE_API_BASE_URL` with a fallback to `http://127.0.0.1:8000`.

  - `frontend/src/components/SignalCard.jsx`: Added cancellation protection against stale async responses during rapid symbol switching.
- **Verification**: `tests/fs_02/test_f48_f57_frontend.py` & Vite production build (`npm run build`).

---

### F05 — Non-transactional Override Failure
- **Changes**:
  - `human_insight_manager.py`: `apply_override_to_signal` now checks `record_override`'s return status and raises `ValueError` if recording fails or reason is blank. It preserves all target prices, stop loss levels, peak potential prices, horizons, and suppression flags from the original signal.
  - `app.py`: Updated override action handler to update `st.session_state` with the returned overridden signal and display errors cleanly if recording fails.
- **Verification**: `tests/fs_02/test_f05_override.py` (passes normal, boundary, and failure cases).

---

### F36 — Ambiguous SELL and Position Intent
- **Changes**:
  - `predictor.py` & `position_planner.py`: Clarified `DOWN` -> `SELL` directional lean vs account action.
  - Disambiguated `SELL` for accounts with 0 holdings vs long holdings. A `SELL` signal with zero holdings returns 0 allocation and does not claim to sell non-existent inventory or short without permission.
- **Verification**: `tests/fs_02/test_f36_position_intent.py`.

---

### F35 — Disconnected Portfolio & Averaging-Down Planner
- **Changes**:
  - `position_planner.py`: Updated `generate_plan` to accept `account_cash` and `committed_cash`. Capital allocation is capped by both remaining symbol capacity (`portfolio_capital * max_position_pct - current_position_inr`) and free account cash (`account_cash - committed_cash`). Missing account cash facts return 0 allocation with explicit notice.
  - `narrative_builder.py`: Updated `build_stock_narrative` to accurately communicate decision, horizon, and model score vs calibrated probability.
- **Verification**: `tests/fs_02/test_f35_position_planner.py`.

---

### F40 — Model Scores Presented as Probabilities
- **Changes**:
  - `predictor.py`: Updated reasoning generation wording from `"raw confidence 0.80"` to `"raw model score 0.80"`.
  - `narrative_builder.py`: Explicitly labels `calibrated_confidence` as calibrated probability when present, and as `"raw model score: X.X% (calibrated probability: unavailable)"` when missing (`None`).
  - `scalping.py`: Explicitly labels intraday conviction ranking score as ranking score rather than historical success probability.
  - `app.py` & `api.py`: Updated table headers and humanized reasoning strings to prevent raw score leakage.
- **Verification**: `tests/fs_02/test_f40_score_presentation.py`.

- **Dated Advisory Scan**: 10 September 2026 scan reported 5 affected packages:
  1. `baseline-browser-mapping` (moderate) — build-time browser list mapping.
  2. `postcss` (moderate) — CSS transformation tooling during Vite build.
  3. `brace-expansion` (high) — glob expansion dependency used in build/lint tools.
  4. `browserslist` (high) — build tool environment configuration parser.

- **Disposition & Reachability**:
