# DA-02 — Prediction History, Outcomes and Storage Integrity

## Assignment
DA-02: Prediction history, outcomes and storage integrity.

## Scope
This implementation addresses the assigned DA-02 findings:
- F11 — Horizon-aware outcome resolution
- F12 — Outcome classification boundary/equality handling
- F20 — Prediction lineage and generation identity
- F38 — Resolution/storage integrity
- F52 — Prediction history storage integrity

## Implementation Summary

### F11 — Horizon-aware outcome resolution
Outcome resolution now uses the recorded prediction entry timestamp and requires the configured number of valid future market observations.

Trading-day validation is applied so weekends and non-trading days do not incorrectly satisfy the prediction horizon.

Pending predictions are processed oldest-first to reduce the possibility of older unresolved predictions being starved by continuously arriving predictions.

### F12 — Outcome classification boundary
Outcome classification uses the configured deadband threshold.

The classification rules are:
- Movement greater than the deadband → `UP`
- Movement less than the negative deadband → `DOWN`
- Movement within the deadband, including equality → `FLAT`

This preserves the required equality behaviour.

### F20 — Prediction lineage
Prediction records retain generation-level provenance, including:
- `generation_id`
- `model_version`
- `feature_version`
- `data_version`
- `label_definition_version`
- `entry_timestamp`
- `entry_price`

Repeated delivery of the same generation is tracked using `delivery_count` rather than creating duplicate prediction records.

Legacy records without available provenance are represented as `UNKNOWN` rather than having provenance inferred from the current model or environment.

### F38 — Resolution integrity
Prediction resolution records the outcome state and resolution metadata.

Resolved predictions are no longer returned when querying unresolved predictions.

Resolution state is persisted together with:
- actual class
- correctness
- entry price
- endpoint price
- entry timestamp
- target timestamp
- resolution status
- resolution reason

### F52 — Storage integrity
Prediction records remain readable after storage operations and unresolved records retain their required prediction and entry information.

SQLite busy-timeout handling is retained for database contention scenarios.
